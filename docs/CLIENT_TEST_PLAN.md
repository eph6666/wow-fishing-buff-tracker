# 客户端验收清单

状态：尚未执行。此环境没有 WoW 客户端；本地回归和 Blizzard 源码契约
测试不能确认真实物品使用、secret/taint 或最终视觉效果。

使用 `v0.3.0` Release 安装包或对应的 `FishingBuffTracker/` 源码目录。
目标是 Retail `12.1.0`；记录实际版本、build、语言、
界面缩放以及其他启用插件，以便复现。

## 1. 加载和基本交互

1. 保留现有账号配置备份后安装源码，执行 `/reload`。
2. 开启错误显示：`/console scriptErrors 1`。
3. 执行 `/fbt` 和 `/fbt status`，确认控制台与状态栏正常出现。
4. 分别测试 `/fbt hide`、`show`、`lock`、`unlock`；用左侧手柄移动，
   `/reload` 后检查位置和锁定状态。
5. 关闭并重开 Settings，改变界面缩放和窗口尺寸；确认顶部控件、最后一列、
   新增区域不越界，滚动可到达最后一行。

通过标准：没有 Lua 错误；显隐和位置可保存；图标与手柄各自能正常响应。

## 2. 真实效果和点击

| 条目 | 操作与记录 | 预期 |

| Toy | 用拥有的可重复使用巨型鱼漂测试 | 玩具动作成功，Aura 激活后更新 |

| 尖刺钉螺 | 装备渔竿 244790，点击 ItemID 262651 对应图标；执行 `/dump C_PaperDollInfo.GetTemporaryEnchantmentInfo(28)` | 一次点击应用成功；返回 enchantID 8675、合理的剩余时间；状态栏显示附魔 |
| 诱饵 | 缺失、激活、到期三个阶段观察 | 非战斗时缺失隐藏、激活显示，到期及时更新 |

用客户端实际的 `ActionButtonUseKeyDown` 设置分别测试按下和松开执行，
记录原值并在测试后恢复。一次完整点击应只触发一次动作。宏启动选取目标
但没有成功应用，也应记录为未通过，而不是“插件没有报错就通过”。

附魔还需测试更换渔竿、应用其他附魔、到期、重新登录。检查装备警告及
`/fbt status` 的栏位/附魔信息。若返回与候选 ID 不同，保存原始结果再修改数据。

## 3. 编辑和战斗切换

1. 修改名称或 ID 时暂不提交，同时获得/失去 Buff、移动背包物品；
   草稿应保留。回车提交一次，Esc 取消。
2. 留下未提交草稿，再排序、删除自定义行、关闭并重开面板；
   草稿不能写入另一条目。
3. 悬停宏条目的 ItemID 和附魔追踪 ID，确认只读说明。普通 Item/Toy
   条目的 ID 仍可编辑。
4. 进入战斗后修改可编辑条目、排序或停用。状态栏图标、提示与点击动作
   应继续对应旧配置；`/fbt status` 提示待应用更改。脱战后应用最终设置。
5. 非战斗开始拖动，进入战斗后松手。确认没有保护调用报错；脱战后位置保存。
   再测试拖动过程中排队 `/fbt reset`，脱战后应停在默认位置。
6. 在战斗中执行显示/隐藏，并在脱战后检查最终请求生效。

通过标准：没有动作与显示错配、错误行被修改、按钮失效或战斗保护错误。
进入战斗时客户端可能自动停止原生拖动；需记录观察到的行为。

## 4. 受限数据与持续运行

在实际会限制 Aura 的场景中观察：不可读取的状态应显示未知；不可读取的
时间或层数应显示 `?`；不能出现 secret 运算、字符串拼接或索引错误。
离开限制场景后应随事件恢复可读状态。没有遇到限制场景不能记为通过。

同时让多个已追踪效果到期，观察状态是否恢复、控制台草稿是否保持、界面是否
卡顿。普通客户端观察无法证明扫描次数上限，扫描节流以本地计数回归为依据。

物品、背包数量、装备、是否战斗和 `ActionButtonUseKeyDown` 值。
