## 1. 加载和基本交互

1. 保留现有账号配置备份后安装源码，执行 `/reload`。
2. 开启错误显示：`/console scriptErrors 1`。
3. 执行 `/fbt` 和 `/fbt status`，确认控制台与状态栏正常出现。
4. 分别测试 `/fbt hide`、`show`、`lock`、`unlock`；用左侧手柄移动，
   `/reload` 后检查位置和锁定状态。
5. 关闭并重开 Settings，改变界面缩放和窗口尺寸；确认顶部控件、最后一列、
   新增区域不越界，滚动可到达最后一行。

通过标准：没有 Lua 错误；显隐和位置可保存；图标与手柄各自能正常响应。

## 3. 编辑和战斗切换

1. 修改名称或 ID 时暂不提交，同时获得/失去 Buff、移动背包物品；
   草稿应保留。回车提交一次，Esc 取消。
2. 留下未提交草稿，再排序或删除自定义行；控件点击造成的失焦会先把编辑
   提交到原条目，不能写入另一条目。关闭并重开面板时，未触发失焦提交的
   草稿应取消。
3. 悬停宏条目的 ItemID 和附魔追踪 ID，确认只读说明。普通 Item/Toy
   条目的 ID 仍可编辑。
4. 进入战斗后修改可编辑条目、排序或停用。状态栏图标、提示与点击动作
   应继续对应旧配置；`/fbt status` 提示待应用更改。脱战后应用最终设置。
5. 非战斗开始拖动，进入战斗后松手。确认没有保护调用报错；脱战后位置保存。
   再测试拖动过程中排队 `/fbt reset`，脱战后应停在默认位置。
6. 在战斗中执行显示/隐藏，并在脱战后检查最终请求生效。

通过标准：没有动作与显示错配、错误行被修改、按钮失效或战斗保护错误。
进入战斗时客户端可能自动停止原生拖动；需记录观察到的行为。

## 4. 受限数据与持续运行

在实际会限制 Aura 的场景中观察：不可读取的状态应显示未知；不可读取的
时间或层数应显示 `?`；不能出现 secret 运算、字符串拼接或索引错误。
离开限制场景后应随事件恢复可读状态。没有遇到限制场景不能记为通过。

同时让多个已追踪效果到期，观察状态是否恢复、控制台草稿是否保持、界面是否
卡顿。普通客户端观察无法证明扫描次数上限，扫描节流以本地计数回归为依据。

`/use item:262651`、`/use 28` 在该客户端能够成功工作，并由插件读取为栏位
28 的附魔 `8675`。尚未覆盖显隐、拖动、设置布局、按下/松开点击次数、战斗
保护或受限数据场景，因此客户端验收仍为“进行中”。

状态栏基础交互实测通过：`/fbt hide`、`show`、`lock`、`unlock` 均正常，
解锁后可通过左侧手柄拖动，执行 `/reload` 后位置能够保存。晶华感知瓶剂因

设置面板实测通过：列表和新增区域未越界，可以滚动到最后一行；名称编辑按
回车能够提交，按 Esc 能够取消。此次未报告 Lua 错误。

战斗中排队显示、隐藏和设置修改均实测通过，但随后捕获到真实受限 Aura
场景的 taint 错误：`AuraUtil.ForEachAura` 内的 `GetAuraSlots()` 不允许由
插件污染路径访问。代码已改为按已配置 SpellID 调用
`C_UnitAuras.GetPlayerAuraBySpellID`。客户端在同类受限 Aura 战斗场景中
持续复测约一分钟，未再出现 `GetAuraSlots()` taint 错误，此项通过。

继续验收时发现战斗中执行 `/fbt` 会让 Settings 调用受保护的
`OpenSettingsPanel()`。设置打开请求现已在战斗中排队，并于
`PLAYER_REGEN_ENABLED` 后自动执行。客户端复测确认：战斗中仅显示延迟
提示，脱战后面板自动打开，未再产生 `ADDON_ACTION_BLOCKED`，此项通过。

客户端分别在 `ActionButtonUseKeyDown=1` 和 `ActionButtonUseKeyDown=0`
时点击插件物品按钮，均确认一次完整点击只执行一次动作、只消耗一个物品；
测试后恢复原 CVar 值，此项通过。

诱饵条目实测通过：缺失时隐藏，使用后自动出现并显示倒计时，效果到期后
自动隐藏；过程中未报告 Lua 错误。

编辑草稿实测通过：名称保持编辑焦点且尚未提交时，Buff 与背包状态刷新不会
覆盖草稿；Esc 能恢复原值，回车能提交一次，过程中未报告 Lua 错误。

进一步实测确认点击排序按钮时，客户端会先让编辑框失焦并提交到原条目，
随后执行排序；不会写入其他条目。尝试在 `OnMouseDown` 提前取消仍早不过
客户端的失焦提交，因此接受并记录该行为，移除无效的提前取消代码。

尖刺钉螺的宏 ItemID 与临时附魔追踪 ID 均实测为只读，悬停说明正常；普通
Item/Toy 条目的对应 ID 仍可编辑，此项通过。

战斗中停用、排序条目实测通过：状态栏保持已应用的旧布局，按钮显示、提示
与点击动作没有错配；`/fbt status` 正确提示设置等待脱战应用，脱战后最终
设置统一生效，过程中未报告 Lua 错误。

多个已追踪 Buff 在接近时间内到期的持续运行测试通过：图标状态和倒计时
及时清除，诱饵按规则隐藏，编辑草稿未丢失，界面无可感知卡顿，未出现新的

本轮客户端验收结论：除晶华感知瓶剂 ItemID `191354` / Aura `393714`
按用户要求跳过外，其余计划项目均通过。客户端过程中发现并复测通过的修复
包括：受限 Aura 的 `GetAuraSlots()` taint、战斗中打开 Settings 的保护
调用，以及战斗拖动松手位置保存错误。

拖动中进入战斗后松手的实测发现：由于 `StopMovingOrSizing()` 在战斗中受
保护，状态栏会继续跟随鼠标，并在脱战时错误保存当时的鼠标位置。修复后会
在战斗中的首次松手事件保存该时刻锚点，脱战停止原生移动后恢复并持久化该
锚点。客户端复测确认脱战后恢复到战斗中松手的位置，且 `/reload` 后位置
保持，此项通过。战斗期间暂时继续跟随鼠标属于受保护 API 限制。拖动过程
进入战斗后执行 `/fbt reset` 也未产生报错，脱战后正确回到默认位置，此项
通过。
